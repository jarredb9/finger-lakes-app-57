# Direct Table RLS Hardening, Column Privilege Revocation, and Private Visit Storage

Direct PostgREST access to public tables must not expose sensitive user data, bypass friendship consent, or allow cache corruption. Rather than elevating `get_friend_profile_with_visits` to `SECURITY DEFINER` (which would breach the strict 7-function allowlist in ADR-0007), `public.profiles` retains `public.is_visible_to_viewer(id)` row-level security for public profile fields while column-level privileges revoke `SELECT (email)` and `UPDATE (id, email)` from `authenticated`. All client identity resolution for self-profiles retrieves email exclusively through `supabase.auth.getUser()`. Furthermore, `public.friends` restricts direct `INSERT` to `status = 'pending'`, `trip_members` restricts collaborator additions to accepted mutual friends while granting non-owner members autonomous self-deletion, and `ensure_winery` validates coordinates, rating bounds, and protocols. The `visit-photos` object storage bucket is strictly private (`public = false`), protected by a `storage.objects` `SELECT` policy backed by an array-containment GIN index on `public.visits (photos)`, and webhook notifications fail open with logged warnings to ensure infrastructure configuration faults never block core user mutations.
