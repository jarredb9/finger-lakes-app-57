# Security Invoker RPC Default and Winery Catalog Immutability

All database RPCs in `public` must execute as `SECURITY INVOKER` by default so PostgreSQL Row-Level Security (RLS) policies remain the single enforcement point for signed-in users, while unauthenticated (`anon`) access and GraphQL schema reflection (`pg_graphql`) are completely disabled. `SECURITY DEFINER` is restricted to an explicit allowlist of functions that must cross RLS boundaries under strict internal `auth.uid()` guards (`ensure_winery`, `is_visible_to_viewer`, `is_trip_member`, `add_trip_member_by_email`, `send_friend_request`, `get_friends_and_requests`, `get_trip_details`, and internal audit/auth triggers). Furthermore, client-callable write flows must resolve wineries exclusively through `ensure_winery` using insert-if-missing / backfill-nulls semantics, preventing regular users from overwriting canonical Winery catalog attributes (`name`, `address`, `latitude`, `longitude`) that belong to `service_role` enrichment.
