# Autonomous Nightly Agent Workflow

Triaged GitHub issues can be resolved overnight using an autonomous multi-stage agent pipeline (`.github/workflows/agent-resolve.yml` driven by the modular `agent_resolve` package in `scripts/agent-resolve/agent_resolve/`, PEP 621 metadata in `scripts/agent-resolve/pyproject.toml`, and the backward-compatible `scripts/agent-resolve/agent-resolve.py` CLI shim) triggered at 20:00 EST (00:00 UTC) or on-demand via `workflow_dispatch`.

To ensure safety on a public repository, control token consumption against Gemini API quotas, and enforce the repository's strict TDD invariants, the workflow adheres to the following principles:

1. **Two-Stage Label Gating**: An issue labeled `ready-for-agent` signifies static triage readiness but will not trigger unattended execution. Only issues explicitly tagged with `agent:resolve` are picked up during the nightly batch (capped at 3 sequential issues per night).
2. **Security & Threat Isolation**:
   - **Author Provenance**: Because the repository is public, issues must be authored by verified repository maintainers (`@jarredb9`) to prevent prompt injection and remote code execution from external issue submissions.
   - **Git Credential Protection**: Configured `actions/checkout@v4` with `persist-credentials: false` so that authorization tokens are never persisted to `.git/config`.
   - **Network-Isolated Test Sandbox**: Verification commands (`npm test`, `npm run type-check`) execute inside an ephemeral Docker container (`node:24-slim`) with `--network none`, matching host UID/GID (`--user "$(id -u):$(id -g)"`), and non-root environment directories (`-e HOME=/tmp -e npm_config_cache=/tmp/.npm`). This completely cuts off outbound network sockets, prevents secret exfiltration from memory or files, and eliminates root-file ownership artifacts.
   - **Path Traversal Protection**: Target file paths are strictly validated against `PROJECT_ROOT` and prohibited from modifying protected paths (`.git/`, `.github/workflows/`, agent scripts).
3. **Structured Schemas & Precision Code Modification**:
   - **Pydantic Validation**: All LLM interactions use strict Pydantic schemas passed to the SDK's `response_schema`: `DiagnosticResult` / `DiagnosticAction` (Stage 0), `BlueprintPlan` (Stage 1), `TestFileManifest` (Stage 2), and `PatchManifest` / `PatchChunk` (Stage 3).
   - **Search/Replace Patch Engine & Retry State Hygiene**: Replaced whole-file rewrites in production source code with targeted search/replace patch chunks (`file_path`, `search_block`, `replace_block`). In Stage 3, target source files are transactionally reset back to baseline (`reset_target_sources`) at the start of each retry attempt to eliminate compounding syntax wreckage or anchor mismatches. On mismatch, exact line-level diagnostics are returned to the model during retry loops.
4. **Canonical Model Endpoint & Strict Hard-Stop Policy**:
   - Standardized strictly on **`gemini-3.8-flash`** across all three stages (Planner and Executors).
   - **No Downgrades**: If `gemini-3.8-flash` cannot be reached or returns an unrecoverable API error, the harness halts immediately (no fallbacks to 2.5 or 1.5). The issue is degraded to `ready-for-human` with error diagnostics posted for morning triage.
   - **Resilient Jitter Backoff & Boundary Regex**: Transient HTTP 429 (`ResourceExhausted`), 500, 502, 503, 504, capacity errors, and network transport/socket drops (`Server disconnected without sending a response`, `RemoteDisconnected`, `ConnectionResetError`, `Timeout`, `BrokenPipeError`) trigger exponential backoff with randomized full jitter (up to 60s). Numeric status codes are matched using boundary regex `r"(?<![0-9,])(?:429|500|502|503|504)(?![0-9,])"` to prevent false-positive retries on formatted token amounts (e.g. `500,000`) or line numbers.
   - **Inter-Issue Batch Pacing**: A configurable pacing delay (default 5s) separates sequential batch issues to avoid rate bursts.
5. **Discounted Cached Token Budget & Observability**:
   - **Discounted Effective Accounting**: Each issue is constrained to a hard token budget cap (`MAX_TOKENS_PER_ISSUE = 500,000`) evaluated against `effective_tokens`. Because Gemini context caching significantly reduces computational overhead and operational cost, cached prompt tokens are accounted at a 25% discount weight (`effective_call_tokens = max(0, total - cached) + int(0.25 * cached)`).
   - **Pre-Call Budget Guard & Retry Handler Isolation**: A pre-flight budget check runs immediately before dispatching each API call and before each backoff retry attempt, failing fast if the budget is exhausted. `record_usage()` is isolated outside the transient retry handler so transient network failures or retries do not trigger redundant budget checks or misclassify budget errors.
   - **Dual Metrics & Observability**: Token metrics format dual metrics (`<effective> effective tokens / <raw> raw total (<prompt> prompt [<cached> cached @ 25%], <candidates> candidates) across <N> API call(s)`) alongside execution duration in the resulting Draft PR body, issue comments, and diagnostic logs.
6. **Git Workspace Isolation, WIP Preservation & Stateful Iterative Resumption**:
   - **Initial Batch Isolation**: Unstarted issues branch from a clean reset of `origin/main` (`git reset --hard`, `git clean -fd`).
   - **WIP Preservation on Failure**: If Stage 3 implementation exhausts its attempts without satisfying verification, the agent does NOT destroy the branch. Instead, uncommitted work is committed as `wip(<scope>): Incomplete implementation for Issue #<num> [skip ci]`. A machine-readable checkpoint (`.agent-state.json`) and diagnostic post-mortem (`AGENT_HANDOFF.md`) are committed as `docs(agent): Checkpoint state for Issue #<num> [skip ci]`. The branch `agent/issue-<num>` is pushed to `origin`, and a Draft PR titled `WIP: fix(<scope>): <title> [FAILED CHECKS]` labeled `ready-for-human` is opened or updated. Diagnostics are staged into an un-tracked `diagnostic-artifacts/` directory before the runner's workspace is reset to `origin/main`, ensuring `actions/upload-artifact@v4` successfully captures post-mortems and batch runs exit non-zero on failure.
   - **Stateful Iterative Resumption**: When an issue is re-tagged with `agent:resolve`, the harness checks for `origin/agent/issue-<num>`. If found, it fetches and checks out the branch, then attempts an automatic rebase onto `origin/main`. If merge conflicts occur, the rebase is aborted (`git rebase --abort`), an issue notice is posted, and the agent falls back to starting fresh from `origin/main`.
   - **Deterministic Red Gate Fast-Forward & Autonomous Checkpoint Invalidation**: If the rebase is clean, the harness reads `.agent-state.json`, rolls target source files back to `red_phase_commit_sha`, and verifies that `npm run type-check` exits 0 and targeted Jest tests fail with verified assertion failures (`validate_jest_red_phase`). If verified, the agent skips Stage 1 and Stage 2 entirely, saving ~200k tokens and jumping directly into Stage 3 Green Phase. If the checkpoint tests crash at runtime (e.g. fatal test harness or mock exceptions), the checkpoint is invalidated, the branch is reset to the blueprint plan commit (`red_phase_commit_sha~1`), and Stage 2 is re-executed with crash diagnostics injected before proceeding to Stage 3.
   - **Resumption Checkpoint Self-Healing & Blast Radius Merging**: When loading `.agent-state.json` during Stateful Iterative Resumption, the harness queries the files modified in `red_phase_commit_sha` via `git diff-tree --no-commit-id --name-only -r <red_sha>`. The loaded `target_test_files` list is sanitized to include only valid Jest test files modified in that commit (falling back to the first 3 valid Jest suites if diff is empty/unavailable). Extra valid test files are demoted to `blast_radius_test_files`, merged with existing blast radius suites, deduplicated, stripped of non-Jest paths, and capped at 8 suites. `BlueprintPlan` is instantiated with the sanitized blast radius suites on both clean resumption and checkpoint invalidation rollback.
   - **VCS Checkpoint & PR Persistence**: `preserve_failed_work` persists `blast_radius_test_files` into `.agent-state.json`, and `update_or_create_pr` formats discovered blast radius suites in the Draft PR summary.
   - **Maintainer Guidance Ingestion**: When resuming, the agent queries issue comments authored strictly by `@jarredb9` posted after the last failure timestamp, injecting maintainer tips into the Green Phase prompt.
   - **Clean Commit History on Success**: When Stage 3 passes on resumption, the branch is soft-reset to `red_phase_commit_sha` (`git reset --soft <sha>`), the temporary `.agent-state.json` and `AGENT_HANDOFF.md` files are removed, and a single clean `feat(<scope>): ...` commit is created. This produces a pristine 3-commit pull request history (`docs(plan)` → `test(...)` → `feat(...)`) with zero traces of broken WIP attempts.
7. **TDD Compiler, Two-Tier Patching & Regression Gates (4-Stage Pipeline)**: 
   - **Stage 0 (Diagnostic Exploration)**: Autonomous read-only exploration loop (`grep_search`, `find_files`, `read_file_snippet`) producing structured `DiagnosticResult` actions that bound maintainer hints and localize reproduction seams before architectural commitment.
   - **Stage 1 (Architectural Blueprint & Test Isolation)**: Formulates `task-plan.md`, explicit target files, and conventional commit scope (`gemini-3.8-flash`), grounded by Stage 0 diagnostics, automated repository source inventory (`get_repository_tree`), `CONTEXT.md`, and `AGENTS.md`. Discovers related test suites using boundary regex and generic stem qualification, sorting by ancestor directory proximity, and capping at 8 suites. Discovered suites not in `target_test_files` are partitioned into `blast_radius_test_files` and strictly isolated from LLM prompts and Stage 2 authoring. Target test paths are validated to exclude `supabase/**`, `e2e/**`, and non-Jest extensions, backed by a 2-attempt self-correction loop in Stage 1 if target test files become empty. Commits `docs(plan): ...`.
   - **Stage 2 (Red Phase Tests & Shared Edge Function Invariant)**: Authors unit/component tests in target test files (`TestFileManifest.files`). For brand new source files in `target_src_files` that do not yet exist on disk, authors minimal TypeScript type declarations and function stubs throwing `'Not implemented'` (`TestFileManifest.source_stubs`) with unused parameters prefixed with `_` to satisfy strict `noUnusedParameters` (`TS6133`). For pure-TypeScript shared Edge Function modules (`supabase/functions/_shared/*.ts`), unit tests MUST be authored in Jest suites under `lib/**/__tests__/*.test.ts` importing via `@/supabase/functions/_shared/<module>` (headless triage permits pure-TS shared modules while flagging Deno runtime entrypoints). Tests must compile cleanly (`npm run type-check`) and fail targeted `jest` execution with verified assertion failures (`validate_jest_red_phase`), prohibiting test-harness crashes (such as `TypeError: Cannot redefine property: location` from JSDOM `window.location` redefinition). Features a 2-attempt self-correction loop for TypeScript compilation and runtime test harness crashes. Commits `test(<scope>): ...`.
   - **Tier 3 Blueprint Invalidation**: Fallback mechanism when Stage 2 test authoring hits an unrecoverable architectural dead end or persistent compilation crash (`Stage2CompilationError`). Re-plans Stage 1 with compiler and harness feedback from a clean reset of `origin/main`.
   - **Stage 3 (Green Phase Implementation, Fail-Fast Compilation & Error Truncation)**: Implements minimal application code with concise search blocks (3 to 10 lines of anchor context). Uses a two-tier search/replace patch engine: Tier 1 strict exact matching, falling back to Tier 2 line-by-line whitespace-trimmed matching (`strip()`) with a strict single-occurrence constraint. Features up to 3 self-correction iterations against targeted tests with immediate console diagnostic logging on every attempt. Prompts inject only `target_test_files` in the `TESTS TO PASS` section to avoid prompt token blowout. Verification executes targeted Jest with `--no-color` and `--silent` against `target_test_files + blast_radius_test_files`, where blast radius suites act strictly as immutable regression guards. Enforces a **fail-fast compiler check**: if `npm run type-check` fails (`tc_code != 0`), targeted Jest execution is skipped entirely on that iteration, populating `last_error_context` solely with compiler errors. Strips ANSI escape sequences and enforces a strict head/tail 8,000 character truncation cap (retaining the first 4,000 and last 4,000 characters with `... [TRUNCATED {chars} CHARS OF VERIFICATION OUTPUT] ...`) on `last_error_context` to prevent context explosion.
   - **Mandatory Full Regression Gate**: Before committing `feat(<scope>): ...` and opening the PR, the agent must pass a fail-fast compiler check (`npm run type-check` runs first) and the entire test suite (`npm test`) cleanly inside the isolated container.
8. **Downstream CI Triggering & In-Place PR Mutation**:
   - **Native CI Status Checks**: The workflow mints an ephemeral token via `actions/create-github-app-token@v1` using `APP_ID` and `APP_PRIVATE_KEY` secrets (falling back to `GITHUB_TOKEN`).
   - **In-Place PR Mutation**: If a WIP Draft PR already exists on `agent/issue-<num>` from a previous failure, the successful resumption updates the existing PR in-place (updating title to remove `WIP:`, replacing the body with passing verification metrics, removing `ready-for-human`, adding `agent:in-review`, and requesting review from `@jarredb9`). The PR remains in Draft state for final human sign-off before merge. If no prior PR exists, a new Draft PR is opened. On final failure, the PR and issue are downgraded to `ready-for-human`.
9. **Modular Package Architecture & Test Infrastructure**:
   - **Package Decomposition**: The monolithic 2,200-line script is decomposed into a modular Python package (`scripts/agent-resolve/agent_resolve/`) structured across focused domain modules: `config`, `models`, `tracker`, `exceptions`, `environment`, `verification`, `patch_engine`, `vcs`, `llm`, `context`, `diagnostics`, `stages`, `pipeline`, and `cli`.
   - **Packaging Metadata**: PEP 621 packaging metadata in `scripts/agent-resolve/pyproject.toml` defines console entrypoint `agent-resolve = "agent_resolve.cli:main"`.
   - **Backward-Compatible Executable Shim**: `scripts/agent-resolve/agent-resolve.py` is preserved as a compact ($\le 80$ lines) executable CLI entrypoint. It features `sys.path` bootstrapping, `importlib.util.spec_from_file_location` loader self-healing, complete `__all__` symbol parity, and dynamic `_ShimModuleProxy(types.ModuleType)` attribute delegation and monkeypatch propagation across modules.
   - **Dual-Suite Verification**: Automated testing is split into modular unit tests in `scripts/agent-resolve/tests/` (`npm run test:agent`) and dual-suite regression verification (`npm run test:agent:all`) ensuring 100% backward compatibility with legacy tests in `scripts/__tests__/`.
